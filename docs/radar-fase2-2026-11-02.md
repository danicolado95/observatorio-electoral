## Cambios estructurales

### Electográfica

- Las lecturas iniciales, estructuras inválidas, duplicados, reconciliaciones previas y recuperación de referencias registran incidencias y continúan con las comprobaciones independientes posibles. Los conflictos previos se enumeran por campo o resultado y por estudio.
- Snapshot ausente, incompleto, vacío o con identidades duplicadas bloquea la promoción. Si contiene entradas legibles, se inspeccionan para producir diagnóstico, sin autorizar la importación del lote.
- Una entrada malformada no interrumpe las demás. Para una identidad reconocida, campo ausente, enlace original ausente y porcentajes incompletos se recogen simultáneamente, en lugar de detenerse en el primer defecto.
- Tipos explícitos: `error` bloquea el lote; `cuarentena` separa un candidato no admitido; `no_evaluable` identifica una comprobación dependiente que no puede completarse; `exclusion_esperada` identifica ámbito regional, canal CIS/modelos y periodo excluido. Las exclusiones siguen también en `quarantine.json` por compatibilidad con el cómputo existente de entradas; su motivo queda tipado en el diagnóstico.
- La fecha de publicación discrepante impide el cruce incluso si no hay porcentajes nuevos. GAD3 con título 19/11/2023 frente al histórico 20/11/2023 permanece en cuarentena. No se modifica ni se elimina su referencia histórica.
- Los informes del intento se guardan como `intento-*.json`. Un lote bloqueado conserva `radar.json`, `audit.json` y los informes aceptados anteriores. `diagnostico.json` y, en caso de bloqueo, `integracion-validacion.json` contienen el resultado agregado. No se presenta una importación correcta como si fuera la auditoría integral final.
- Inventario de fuentes leídas con estado, hash, registros y referencias; cobertura por entrada, incluidas identidades ausentes y duplicadas. El JSON conserva evidencias y no ejecuta HTML ni URLs de las fuentes.

### Wikipedia

- La preparación acumula errores de lectura, revisión manual modificada, originales no verificados, candidatos inválidos, duplicados, conflictos históricos, referencias y posibles republicaciones. Los rechazos de validación estricta bloquean el lote: no se guarda una selección parcial de candidatos válidos.
- Los cambios en metadatos históricos también bloquean, además de los conflictos en porcentajes. Se mantiene la llamada al validador estricto existente.
- La extracción Python deja `diagnostico-extraccion.json` al fallar y conserva el staging anterior. Una extracción correcta renueva ese diagnóstico, evitando un fallo antiguo presentado como actual.
- Se admite una raíz aislada de pruebas mediante `ELECTOGRAFICA_TEST_ROOT`, sin cambiar los destinos habituales cuando no está definida.

### Escritura del lote

`lote-atomico.mjs` prepara todos los archivos aceptados antes de promoverlos y sustituye el radar al final. Ante un fallo recuperable de escritura, restaura los archivos anteriores y retira temporales. Una prueba provoca un fallo después de cambiar la auditoría y exige recuperar exactamente sus bytes y los del radar.

Esto protege frente a fallos de E/S capturables. No es una transacción de sistema de archivos resistente a corte eléctrico ni incorpora exclusión entre procesos concurrentes; ejecutar los runners de forma secuencial.

## Límites y riesgos pendientes

- Las dos pruebas omitidas de JavaScript requieren el snapshot completo real de Electográfica, todavía ausente. No se han eliminado sus omisiones ni fabricado ese snapshot.
- La E2E protege el histórico utilizado como entrada; no acredita que los adaptadores puedan reconstruir las 480 privadas, 35 CIS y 233 referencias exclusivamente desde HTML/feed originales. Tampoco recorre todas las revisiones manuales reales: sus colecciones de revisión del fixture son vacías.
- Se enumeran incidencias independientes de lotes y registros evaluables. Cuando falta una identidad, una fuente o una estructura necesaria, las comprobaciones que dependen de ella no pueden demostrar resultados; no se inventan candidatos ni se autoriza el lote por ese motivo. El parser Python conserva su bloqueo de documento si faltan revisión permanente o licencia.
- Una cuarentena no demuestra que la discrepancia se haya resuelto. El lote puede conservar las entradas admitidas y el histórico mientras las entradas rechazadas quedan explícitamente fuera. El diagnóstico distingue ese caso de un error estructural, que impide toda promoción.
- La recuperación de escrituras no garantiza recuperación automática tras apagado o fallo persistente del disco. Una recuperación fallida produce error agregado y exige revisar los archivos antes de volver a ejecutar.
- No se ha verificado ejecución en GitHub Actions ni se certifica publicación automática. El runner está preparado para hacerlo posteriormente, bajo revisión del usuario.
